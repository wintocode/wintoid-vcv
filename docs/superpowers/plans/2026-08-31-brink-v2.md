# Brink V2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an independent Brink V2 module with exactly Brink V1's signal behaviour and a FourV2/VortexV2-style SEM panel, while leaving Brink V1 and the future MetaModule wrapper untouched.

**Architecture:** Reuse the Rack-independent `brink` processing types from `src/Brink/dsp.h` and create a separate `BrinkV2` Rack wrapper with its own widget/layout source. Generate the 16 HP V2 faceplate and layout header from one deterministic Python generator; use standard Rack controls and non-interactive layer-1 graphics only. Add source-level MetaModule compatibility checks and a handoff note, but do not edit the sibling MetaModule project.

**Tech Stack:** C++11, VCV Rack 2 SDK, NanoVG, Python 3 standard-library panel generators/tests, standalone C++ Brink DSP tests with AddressSanitizer and UndefinedBehaviorSanitizer, and the existing MetaModule compatibility contract.

**Spec:** `docs/superpowers/specs/2026-08-26-brink-design.md` for the unchanged Brink behaviour contract, plus the approved conversation decisions for the V2 SEM panel, uniform socket treatment, and separate model identity.

## Global Constraints

- Preserve the existing `Brink` model, source, panel, layout, parameter IDs, input/output/light IDs, DSP behaviour, and patch compatibility.
- Register a new model with the permanent slug `BrinkV2`; use `BrinkV2` in manifest metadata and `Brink V2` as the panel title.
- Reuse `src/Brink/dsp.h`; do not copy or alter Brink's window/logic algorithms for V2.
- Keep Brink V2 at 16 HP and 128.5 mm height with the existing two-channel port order, A-to-B normalisation, 1-to-16 VCV polyphony, event pulse timing, reset behaviour, and shared logic.
- Use the V2 SEM palette: ivory background, charcoal text/controls, blue-grey structure, orange functional accents, and the canonical outlined wintoid logo.
- Render every Brink V2 input and output socket with the same panel guide treatment. Do not add an output-only backplate, ring, fill, or colour convention.
- Use ordinary Rack knobs, trimpots, `PJ301MPort` inputs/outputs, and lights for interaction. Custom graphics are read-only, draw on layer 1, stay inside their widget boxes, explicitly select `res/fonts/DejaVuSans.ttf`, and never handle clicks, drags, menus, or parameter writes.
- Keep dynamic visualisation opportunistic and rate-independent; the audio thread may publish the first-lane window snapshot at the existing 60 Hz limit.
- VCV remains 16-channel. The later MetaModule consumer may expose fewer lanes, but that consumer constraint must not reduce VCV behaviour.
- Ensure BrinkV2 is not omitted by any module-discovery or packaging list: the root build source wildcard must compile `src/BrinkV2/BrinkV2.cpp`, the manifest must list the model, and the generated distribution/install package must contain the updated manifest and plugin binary.
- The sibling `../wintoid-metamodule` project is read-only from this plan. Do not modify its source checkout, metadata, assets, SDK, or build files.
- After any source, panel, or `res/` change, build the plugin, run `make install` from the repository root, and fully relaunch VCV Rack before making visual claims.

## Final visual refinements

- Brink V2 was expanded to 16 HP after visual review; it remains 128.5 mm tall.
- The two channel pairs are centred in their group boxes, with equal painted socket clearance on both sides.
- The four event and logic columns share one pitch in the order A LOW, A HIGH, B LOW, B HIGH.
- The shared logic divider was removed, event arrows were enlarged and neutralised, and the title/logo/group-box alignment was made consistent with the other V2 panels.
- Labels above controls and sockets were moved down slightly to favour the item they describe; CHANNEL A and CHANNEL B use bold weight in both generated SVG and Rack schema.
