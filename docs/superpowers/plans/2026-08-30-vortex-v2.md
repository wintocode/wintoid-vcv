# VortexV2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build VortexV2 as a separate twelve-output, MetaModule-compatible-by-construction multi-mode filter while preserving the existing Vortex module unchanged.

**Architecture:** Reuse the filter primitives in `src/Vortex/dsp.h` through a new `src/VortexV2/dsp.h` bank layer. VortexV2 owns independent filter state for each of twelve output modes and each of sixteen VCV lanes, gates each branch with standard output connection state, and resets branches on disconnection. A generated 20 HP panel provides the three existing control groups and a first-fit 3x4 output matrix; the generator and geometry tests can later move the matrix to 2x6 or widen the panel without changing the DSP or output IDs.

**Tech Stack:** C++11, VCV Rack SDK, existing `wintoid::polyphony` helpers, Python 3 deterministic SVG/layout generators, standalone C++ host tests with AddressSanitizer/UndefinedBehaviorSanitizer, and Python `unittest` panel/source-contract tests.

**Spec:** `docs/superpowers/specs/2026-08-30-vortex-v2-design.md`

## Global Constraints

- Preserve the existing `VortexMM` model, source, panel, IDs, and behavior.
- Register a new model with the permanent slug `VortexV2` and name `VortexV2`.
- Keep the shared source C++11-compatible and avoid new dependencies.
- Use standard Rack knobs, trimpots, inputs, and outputs for every interactive element.
- The twelve outputs retain Vortex's existing mode order and DSP meaning.
- Every branch receives the same input lane and the same effective Cutoff, Resonance, and Drive values.
- VortexV2 has no filter-mode parameter and no interactive mode display.
- The initial fit target is 20 HP (101.6 mm) by 3U (128.5 mm).
- The initial implementation deliberately favors independent branch state and behavioral clarity over shared-stage optimization.
- This project does not include changes to the sibling MetaModule wrapper, MetaModule assets or packaging, SDK probes, firmware, or hardware validation.
- After source, panel, or `res/` changes, run the repository install target with `make install` and fully relaunch VCV Rack for visual verification.

- [ ] **Step 3: Implement the minimal independent-state DSP header.**

Define the twelve modes in exactly this order:

```cpp
enum OutputMode {
    LP6 = 0, LP12, LP24,
    HP6, HP12, HP24,
    BP, BP_PLUS,
    NOTCH, NOTCH_PLUS,
    AP, AP_PLUS
};

static const OutputMode OUTPUT_MODES[OUTPUT_COUNT] = {
    LP6, LP12, LP24, HP6, HP12, HP24,
    BP, BP_PLUS, NOTCH, NOTCH_PLUS, AP, AP_PLUS
};

struct BranchState {
    vortex::Filter1 f1;
    vortex::Filter2 f2a;
    vortex::Filter2 f2b;

    void reset() {
        f1.reset();
        f2a.reset();
        f2b.reset();
    }
};

struct VoiceState {
    BranchState branches[OUTPUT_COUNT];

    void reset() {
        for (int output = 0; output < OUTPUT_COUNT; ++output)
            branches[output].reset();
    }
};
```

Implement `process_branch()` as the twelve-case Vortex switch using the branch's own `f1`, `f2a`, and `f2b`. A `+` mode must configure/process `f2a` and then `f2b`; a non-`+` second-order mode uses only `f2a`. Return `0.f` for an invalid mode. Do not share state between output modes in this first implementation.

```cpp
for (int output = 0; output < vortex_v2::OUTPUT_COUNT; ++output) {
    const int outputId = outputIds[output];
    const bool connected = outputs[outputId].isConnected();
    if (!connected) {
        if (previousOutputConnected[output]) {
```

- [ ] **Step 4: Implement the shared control calculation and connected-branch lane loop.**

Match Vortex's control equations exactly: read/broadcast CVs, multiply Cutoff by `vortex::voct_to_mult()`, clamp Cutoff to `20.f..20000.f`, convert Resonance to damping with `0.707f * (1.f - resonance) + 0.01f * resonance`, clamp CV-adjusted damping to `0.01f..0.707f`, add Drive CV scaled by `/ 10.f`, clamp Drive to `0.f..1.f`, and apply `vortex::soft_clip(signal * (1.f + drive * 9.f))` when Drive is positive.

```cpp
for (int lane = 0; lane < channels; ++lane) {
    float signal = readBroadcast(inputs[AUDIO_INPUT], lane) / 5.f;
    // Calculate cutoff, damping, drive, and apply the Vortex drive stage.

    for (int output = 0; output < vortex_v2::OUTPUT_COUNT; ++output) {
        if (!previousOutputConnected[output])

            voiceStates[lane].branches[output],
            vortex_v2::OUTPUT_MODES[output], signal,
            args.sampleRate, cutoff, damping);
        outputs[outputIds[output]].setVoltage(wet * 5.f, lane);

}
```

Flush every `f1.z`, `f2a.z0`, `f2a.z1`, `f2b.z0`, and `f2b.z1` state in each connected branch immediately after processing. Disconnected branches remain reset and are skipped. Preserve the existing Vortex sample-rate reset and `onReset()` behavior.
